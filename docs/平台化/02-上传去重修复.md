# 上传去重导致的「文档不存在或无权访问」修复

- 现象：管理员删除某个 `.docx` 后，普通用户重新上传同一个文件，前端提示「该文档已存在，直接打开」，随后又提示「文档不存在或无权访问」。
- 根因：上传去重查询只按 `tenant_id + sha256` 匹配，没有限定 `user_id`。租户内其他用户（或管理员的另一份副本）仍处于 `ready` 状态时，接口会把该文档当作本次上传的重复项返回，普通用户无权打开。
- 修复：去重条件改为 `tenant_id + user_id + sha256`，并且只匹配 `ready/needs_review` 且 `deleted_at IS NULL` 的文档。这样：
  - 当前用户删除自己的文档后，重新上传会新建文档；
  - 不会把其他用户的文档 ID 返回给当前用户；
  - 同一用户重复上传仍会正常去重。

验证：

- 普通用户 `demo` 重新上传 `AI评测集有什么用.docx`，返回 `deduplicated=false`，创建 `doc_bacd6c40fc`；
- 解析任务完成，状态 `done / 100`；
- 管理员已有的同哈希文档 `doc_687acddb19` 不再影响普通用户上传。

代码位置：`alun/app/pipeline.py::create_document`。
