# 解析失败的依赖缺失诊断

## 现象

`企业级Agent开发全流程_V1.0.docx` 上传后卡片显示「解析失败」，文档记录为：

```json
{"code": "PARSE_FAILED", "message": "No module named 'httpx'", "stage": "parse"}
```

## 诊断

- `.docx` 文件本身可读，大小 758 KB；不是文档损坏；
- 失败发生在解析阶段，不是上传阶段；
- 当前 Python 运行时被切换/更新后，`httpx`、`pymupdf` 等应用依赖没有安装在新的 `site-packages`，而旧进程仍在内存中运行，导致新任务/worker 导入失败。

检查：

```powershell
python -c "import httpx, pymupdf, fastapi, psycopg; print('deps ok')"
```

## 修复

```powershell
python -m pip install --disable-pip-version-check -r alun/requirements.txt
```

然后重启 API 服务和队列 worker，打开失败文档点击「重新解析」。

## 验证

重新解析 `doc_287ef5e2e9`：

- 状态：`ready`
- 质量：`pass / 0.906`
- 结构：137 个章节、245 个知识点、110 个表格、251 个节点
- 解析耗时：约 6.8 秒

同时把 `pipeline.py` 的异常处理改为：缺少模块时返回 `DEPENDENCY_MISSING`，提示安装 `requirements.txt`，不再只显示原始模块名。

## 预防

- 部署时固定使用项目虚拟环境，安装 `requirements.txt` 后再启动 API/worker；
- 升级运行时后执行一次依赖自检；
- 解析失败页面保留「重新解析」入口，依赖修复后无需重新上传文件。
